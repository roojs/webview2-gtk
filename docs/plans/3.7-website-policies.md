## Purpose

- 🔷 Emulate WebKitGTK **`WebsitePolicies`** + **`AutoplayPolicy`** so shared Vala can set construct `website_policies` on Windows the same as Linux.
- 🔷 Emulate **`enable_developer_extras`** + minimal **`WebInspector`** so Snappr can call `get_settings().enable_developer_extras = true` and `get_inspector().show()` without `#if`.
- 🔷 Emulate Snappr’s Browser media/`#if LINUX` block: `enable_media_stream`, `enable_webrtc`, `media_playback_requires_user_gesture`, `is_muted`, `permission_request`, `query_permission_state`.
- 🔷 Honor both on the host where possible (`DENY` autoplay; DevTools window via existing `OpenDevToolsWindow`; mute; PermissionRequested deny).
- 🔷 Snappr must drop the `#if LINUX` forks around policies, developer extras, inspector show, and the media/permission block in `WebViewAuto` / `Browser` / `AutoManager`.
- 🚫 Do **not** invent non-WebKit property names.

## Host mapping (Windows)

WebView2 has **no** `WebsitePolicies` COM type. Autoplay is controlled via Chromium flag on environment create (`ICoreWebView2EnvironmentOptions::AdditionalBrowserArguments`), same channel as `WEBKIT_INSPECTOR_SERVER` → `--remote-debugging-port` ([`win32-ui-webview2-automation.c`](../../lib/host/win32-ui-webview2-automation.c)).

| `AutoplayPolicy` | Additional browser arg (merge into existing options string) |
|------------------|--------------------------------------------------------------|
| `DENY` | `--autoplay-policy=user-gesture-required` |
| `ALLOW` | omit / default (or `--autoplay-policy=no-user-gesture-required` only if we must force allow) |
| `ALLOW_WITHOUT_SOUND` | 💩 omit for v1 (Chromium default is closer to muted-autoplay allowed); document as approximate |

ℹ️ Process limitation today: **one WebView2 environment per process**. Autoplay args must be decided **before** `CreateCoreWebView2EnvironmentWithOptions`. Same rule as inspector port.

**Apply timing:**

1. Vala `construct` on `WebView` reads `website_policies.autoplay` (default `ALLOW` if policies null).
2. If `DENY`, call host `vala_webview2_host_set_autoplay_policy(DENY)` **before** attach/create.
3. Host merges flag when building `EnvOptions` additional args (alongside remote-debugging).

💩 If environment already exists when DENY is requested, `warning` once and document the singleton limitation (same class of issue as late `WEBKIT_INSPECTOR_SERVER`).

### 7b. `WebInspector` (minimal)

#### Add (`lib/webview2gtk/WebInspector.vala`)

```vala
namespace WebView2Gtk {

/**
 * WebKitGTK-shaped inspector — {@link show} opens the host DevTools window.
 */
public class WebInspector : Object {
	private weak WebView view;

	internal WebInspector(WebView view) {
		this.view = view;
	}

	public void show() {
		if (this.view == null) {
			return;
		}
		if (!this.view.get_settings().enable_developer_extras) {
			return;
		}
		this.view.open_devtools_window();
	}

	public void close() {
		/* WebView2 has no close-devtools API; no-op. */
	}
}

}
```

## 9. Media settings, mute, permission signals (Browser `#if LINUX` block)

**Why:** Snappr `Browser.vala` still `#if LINUX`s this block — same urgency as policies/inspector.

```vala
this.web_view.get_settings().enable_media_stream = false;
this.web_view.get_settings().enable_webrtc = false;
this.web_view.get_settings().media_playback_requires_user_gesture = true;
this.web_view.is_muted = true;
this.web_view.permission_request.connect((request) => {
	request.deny();
	return true;
});
this.web_view.query_permission_state.connect((query) => {
	query.finish(PermissionState.DENIED);
	return true;
});
```

### 9a. `WebViewSettings` properties

#### Add

```vala
	public bool enable_media_stream { get; set; default = true; }
	public bool enable_webrtc { get; set; default = true; }
	public bool media_playback_requires_user_gesture { get; set; default = false; }
```

Defaults match WebKitGTK (enabled / no gesture required). Snappr turns them restrictive.

When `media_playback_requires_user_gesture` becomes true **before** env create, merge the same `--autoplay-policy=user-gesture-required` used for `AutoplayPolicy.DENY` (or call `set_autoplay_policy(DENY)`). Late change after env create: store only + `warning` (singleton env limitation).

### 9b. `WebView.is_muted`

#### Add

```vala
	public bool is_muted { get; set; }
```

Honor via `ICoreWebView2_8::put_IsMuted` / `get_IsMuted` (QI from core webview). Apply on attach when ready and whenever the property changes.

### 9c. Permission API surface

WebKitGTK shapes Snappr uses:

```vala
public enum PermissionState { GRANTED, DENIED, PROMPT }

public interface PermissionRequest : Object {
	public abstract void allow();
	public abstract void deny();
}

public class PermissionStateQuery : Object {
	public void finish(PermissionState state);
	public unowned string get_name();
}

/* on WebView */
public signal bool permission_request(PermissionRequest permission_request);
public signal bool query_permission_state(PermissionStateQuery query);
```

### 9d. Host — honour deny

- Register `PermissionRequested` on the core webview at setup.
- Emit Vala `permission_request` with a request object; if a handler returns true, use allow/deny from that object; otherwise:
  - if `enable_media_stream == false` or `enable_webrtc == false` → deny camera/mic (and deny other kinds when Snappr-style “deny all” handler is absent — prefer deny when no handler handled it).
- Set `COREWEBVIEW2_PERMISSION_STATE_DENY` (or Allow) + `Handled = TRUE` so Edge UI does not prompt.
- Push settings flags to host when Vala settings change (`vala_webview2_host_set_media_flags`).
- `query_permission_state`: signal exists for API parity. WebView2 has no direct twin — 💩 do not invent host emits unless a real query path appears; Snappr’s connect still compiles and runs if we never emit.
