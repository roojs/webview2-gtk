## Purpose

🔷 Expose **page accessibility** from the hosted WebView2 so apps can:

- walk the **UIA tree** (name, role/control type, value, bounds, invoke-able / editable)
- **press** (invoke) a node
- **fill** (set value or key-synth into) a node

🔷 This library owns the **Windows / WebView2 / UIA** plumbing. Apps keep their own platform-specific Vala that calls into webview2-gtk.

🚫 Do **not** scrape the DOM / inject page JS for a11y. Prefer the platform accessibility tree (same idea as Linux AT-SPI on GTK/WebKit stacks).

🚫 Do **not** invent app-specific markdown formatting inside this library — return structured node data (or a thin debug string). Apps own debug markdown if they want it.

---

## Why this repo

🔷 Apps already browse on Windows via **this** library (cookies, headers, capture, print, script). Missing piece is a11y control.

🔷 Host today (`lib/host/webview2gtk-host-api.h`) has navigate / script / cookies / screenshot / print — **no** automation-provider or UIA APIs.

🔷 WebView2 maps HTML/ARIA → **UI Automation**. Entry point for Win32 hosts:

- `ICoreWebView2Environment4.GetAutomationProviderForWindow(HWND, IUnknown**)`
- Hosts that need correct tree placement may implement `IRawElementProviderHwndOverride` and call the above from `GetOverrideProviderForHwnd`

ℹ️ Docs:  
- [WebView2 accessibility overview](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/overview-features-apis)  
- [ICoreWebView2Environment4](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2environment4)

## Consumer contract

Apps typically want a dump / fill / press style backend (often mirroring Linux AT-SPI). **Do not implement app code in this plan** — only the library surface below.

Illustrative app-facing shape (owned by the app, not this repo):

```vala
public async string dump(string url, string title) throws GLib.Error;  // debug only
public async void fill(Gee.HashMap<string, string> fields) throws GLib.Error;
public async void press(int id) throws GLib.Error;
// press_routes: id → opaque child-index / RuntimeId path
```

🔷 **`dump` markdown is debug-only** in typical apps — automation uses press-routes / structured tree, not parsing markdown.

🔷 Library should therefore prioritize:

1. **Stable node identity** (route / RuntimeId path) for press/fill after a walk  
2. **Walk** returning name, control type / role, value, bounds, flags (invoke / set-value)  
3. **Invoke** and **SetValue** (or documented keyboard fill) by node id/route  

Markdown projection can stay in the app (or a tiny optional debug helper here).

## Proposed library surface (💩 sketch — spike may change)

Add to host C API + Vala `WebView` wrappers (names flexible):

```c
/* Opaque walk result — exact packing TBD after UIA spike */
typedef struct WebView2GtkA11yNode {
	int id;                 /* press-ref style id for this walk */
	int parent_id;          /* -1 for root */
	int x, y, w, h;         /* client or window coords — document which */
	char *name;
	char *role;             /* ControlType or localized type string */
	char *value;
	char *uri;              /* if hyperlink / value pattern exposes URL */
	bool can_invoke;
	bool can_set_value;
} WebView2GtkA11yNode;

bool vala_webview2_host_a11y_walk (WebView2GtkA11yNode **nodes_out, size_t *count_out);
void vala_webview2_host_a11y_nodes_free (WebView2GtkA11yNode *nodes, size_t count);
bool vala_webview2_host_a11y_invoke (int id);
bool vala_webview2_host_a11y_set_value (int id, const char *utf8);
```

Vala side: **`Win32Atspi`** (`Accessible`, `do_action`, `set_text_contents`, …).  
Host UIA walk/invoke/set_value stay behind that facade — **not** on `WebView2Gtk.WebView`.

🚫 Do not require apps to speak raw COM / UIA from Vala.

## Open points

💩 ⏳ COM apartment / threading — UIA often wants STA; GTK main loop is already STA-ish on Win32. Confirm whether walk/invoke must stay on the UI thread (unlike Linux AT-SPI worker threads).

💩 ⏳ Element lifetime — cache `IUIAutomationElement` vs re-walk by RuntimeId after navigation.

💩 ⏳ Scroll / off-screen names — Linux AT-SPI often scrolls bottom→top before dump; does WebView2 UIA need the same?

💩 ⏳ Coordinate space for `{x,y}` — WebView client vs screen vs GTK allocation.

💩 ⏳ Multi-WebView — host is still **one WebView2 per process** (v0.1 limitation). A11y API can assume the singleton for now.
