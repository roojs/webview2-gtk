## Purpose

- 🔷 Match **WebKitGTK** page→host messages: `UserContentManager.register_script_message_handler` + `script_message_received`.
- 🔷 Page JS: `window.webkit.messageHandlers.<name>.postMessage(…)`.
- 🔷 Host→page replies via existing `evaluate_javascript`.

---

## API copied from WebKitGTK 6

```vala
public unowned UserContentManager get_user_content_manager ();

public sealed class UserContentManager : Object {
	public UserContentManager ();
	public bool register_script_message_handler (string name, string? world_name);
	public void unregister_script_message_handler (string name, string? world_name);
	[Signal (detailed = true)]
	public signal void script_message_received (JavaScriptResult values); // WebKit: JSC.Value
}
```

```js
window.webkit.messageHandlers.foo.postMessage({ hello: "world" });
```

Out of scope: `register_script_message_handler_with_reply`, user scripts/styles, multi-WebView.

---

## Implementation notes

- Host: `lib/host/win32-ui-webview2-script-messages.c` — `WebMessageReceived` + document-created script installing `webkit.messageHandlers`.
- Wire format (internal): `chrome.webview.postMessage(name + "\\n" + JSON.stringify(value))`.
- Smoke: `examples/hello` registers `"ping"` and echoes via `evaluate_javascript`.
