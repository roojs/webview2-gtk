## Purpose

- 🔷 Make `NetworkSession.set_proxy_settings(mode, settings)` actually route HTTP(S) through the configured proxy on Windows (today it is an empty stub).
- 🔷 Keep the public surface identical to WebKitGTK so shared Vala compiles under `using WebView2Gtk` / `using WebKit`.
- 🔷 Honor modes via WebView2 `ICoreWebView2EnvironmentOptions::AdditionalBrowserArguments` at **environment create** (process-wide shared `g_env`).
- 🔷 Document create-time limitation vs WebKitGTK live mid-session change.

---

## Why this matters

- 🔷 Private app already calls the WebKit-shaped API before `load_uri`; Linux works, Windows silently ignores.
- 🔷 Types (`NetworkProxyMode`, `NetworkProxySettings`) already ship — only the host latch + arg merge is missing.
- ℹ️ Same pattern as `navigator_webdriver_active_policy` / autoplay DENY: latch globals → merge into `AdditionalBrowserArguments` on first env create.

## WebKitGTK surface (keep existing names)

Already in tree / VAPI (do **not** rename):

```vala
public enum NetworkProxyMode {
	DEFAULT,
	CUSTOM,
	NONE
}

public class NetworkProxySettings : Object {
	public NetworkProxySettings(string default_proxy_uri, string? http_proxy_uri = null);
}

/* on NetworkSession */
public void set_proxy_settings(NetworkProxyMode mode, NetworkProxySettings? settings);
```

Shared Vala usage (must work on Windows):

```vala
web_view.network_session.set_proxy_settings(
	NetworkProxyMode.CUSTOM,
	new NetworkProxySettings("http://127.0.0.1:8888", null)
);
web_view.load_uri("https://example.test/");
```

ℹ️ WebKitGTK’s C ctor is `(default_proxy_uri, ignore_hosts: string[])`; this library already shipped `(default_proxy_uri, http_proxy_uri?)`. **Keep the shipped ctor** — apps already use it (bug sample). 💩 Scheme-specific `add_proxy_for_scheme` / ignore_hosts stay out of MVP.

## WebView2 mapping

| Mode | Host behavior |
|------|----------------|
| `CUSTOM` + URI | merge `--proxy-server=<uri>` (prefer `http_proxy_uri` if non-null/non-empty, else `default_proxy_uri`) |
| `NONE` | merge `--no-proxy-server` |
| `DEFAULT` | omit both proxy flags (system / WebView2 default) |

Merge into the existing `vala_webview2_host_create_environment_options` builder alongside CDP / autoplay / AutomationControlled.

### Process-wide env (hard constraint today)

- 🔷 One shared `g_env` for the process ([plan 4.0](./4.0-multi-webview-host.md)). Plain `--proxy-server=` applies to **all** WebView2 controllers from that env.
- 🔷 First call **before** env create latches args for the next create.
- 🔷 Call after env exists: **warn once**, store only — **5.0 does not auto-rebuild** the environment. Live switch needs a new env (and thus new controllers).
- ℹ️ WebKitGTK can change a live `NetworkSession`; WebView2 Chromium flags cannot without recreate.

## Product use case — ChatGPT via CA proxy, everything else direct

🔷 Real consumer pattern: ChatGPT WebView traffic relays through a California proxy; other fetching should stay direct.

| Situation | Possible with 5.0 MVP? | Notes |
|-----------|------------------------|-------|
| ChatGPT in WebView2 **+** “other fetching” is Soup / non-WebView HTTP | ✅ Yes | Only WebView2 sees `--proxy-server`; Soup is unaffected. |
| **Two WebViews at once** — one must use CA proxy, one must be direct | ❌ Not with shared env + bare `--proxy-server` | Same `g_env` ⇒ same proxy for all controllers. |
| **Same process, switch over time** — set CUSTOM for ChatGPT session, later want DEFAULT/direct | ❌ Not live | Would need **tear down env + all controllers, recreate** with new flags. 5.0 does **not** implement that rebuild. |
| **One env, host-based split** — `chatgpt.com` (etc.) → CA proxy, all other hosts → `DIRECT` | ⏳ Possible later | Chromium `--proxy-pac-url=` or careful `--proxy-server` + `--proxy-bypass-list`. PAC matches the product intent best. Not in 5.0 MVP unless we promote it. |
| **One env per `NetworkSession`** with different args | ⏳ Architecture follow-on | True WebKit-like per-session proxy; multi-env host redesign (CDP port, lifetime, cost). |

### Open points (resolved for MVP consumer pattern)

1. 🔷 **ChatGPT window + local intelligent proxy:** consumer runs a local forwarder; `set_proxy_settings(CUSTOM, local)` for the life of that one browser window; local proxy routes by request host. Other non-WebView fetching stays direct. ✅ fits 5.0.
2. 🔷 **One browser at a time:** set proxy before attach; when the window closes / next window opens, latch again before the next env create (after last host released `g_env`, or new process). Mid-window live switch still not supported.
3. ⏳ PAC / multi-env / auto-rebuild remain optional if a future app needs concurrent different proxies without a local router.

## Work slices

### 5.1 Host latch + `AdditionalBrowserArguments` merge

**Why:** Chromium only reads `--proxy-server` / `--no-proxy-server` at environment create.

**Add** to `lib/host/win32-ui-webview2-automation.h` / `.c` and `webview2gtk-host-api.h`:

```c
/* 0=DEFAULT, 1=CUSTOM, 2=NONE — match NetworkProxyMode */
void vala_webview2_host_set_proxy_settings (int mode, const char *proxy_uri_utf8);
```

Internals:

- Static `g_proxy_mode` (default `0` / DEFAULT) + `g_proxy_uri` (UTF-8, owned; cleared on DEFAULT/NONE).
- Setter: copy URI when `mode == CUSTOM`; free/clear otherwise. If `g_env != NULL` (need a small accessor or `#include` / weak check — 💩 prefer `vala_webview2_com_get_environment() != NULL` from com-glue, or a `vala_webview2_host_environment_created()` bool), print a one-shot stderr / allow Vala to warn; still update stored values.
- In `vala_webview2_host_create_environment_options`:
  - Treat proxy as another `need_*` so options are created when only proxy is set.
  - Append space-separated `--proxy-server=…` or `--no-proxy-server`.
  - `DEFAULT`: append nothing (and ensure a prior CUSTOM does not leave stale state — setter must clear URI when switching back).
- UTF-8 → wide for the args buffer; bump `args[512]` if needed when combining with CDP + autoplay + webdriver + long proxy URI (💩 `args[768]` or dynamic).

**Do not** invent a Windows-only public Vala API for proxy flags.

### 5.2 Vala `NetworkSession.set_proxy_settings` implementation

**Why:** API shape already public; fill the stub.

**Replace** empty body in `lib/webview2gtk/NetworkSession.vala` with roughly:

```vala
private NetworkProxyMode proxy_mode = NetworkProxyMode.DEFAULT;
private NetworkProxySettings? proxy_settings = null;
private bool proxy_late_warned = false;

public void set_proxy_settings(
	NetworkProxyMode mode,
	NetworkProxySettings? settings
) {
	this.proxy_mode = mode;
	this.proxy_settings = (mode == NetworkProxyMode.CUSTOM) ? settings : null;

	string? uri = null;
	if (mode == NetworkProxyMode.CUSTOM && settings != null) {
		if (settings.http_proxy_uri != null && settings.http_proxy_uri.length > 0) {
			uri = settings.http_proxy_uri;
		} else {
			uri = settings.default_proxy_uri;
		}
	}

	if (wv2_host_environment_created() && !this.proxy_late_warned) {
		this.proxy_late_warned = true;
		warning(
			"WebView2Gtk: set_proxy_settings after env create — stored only; restart required for Chromium proxy flags"
		);
	}

	wv2_host_set_proxy_settings((int) mode, uri);
}
```

Externs next to other `wv2_host_*` in `webview.vala` (or a small shared bindings file if one already groups host decls — follow existing pattern):

```vala
[CCode(cheader_filename = "webview2gtk-host-api.h", cname = "vala_webview2_host_set_proxy_settings")]
extern void wv2_host_set_proxy_settings(int mode, string? proxy_uri);

[CCode(cheader_filename = "webview2gtk-host-api.h", cname = "vala_webview2_host_environment_created")]
extern bool wv2_host_environment_created();
```

💩 Exact “env created” helper name is flexible; match com-glue (`g_env != NULL`).

`CUSTOM` with `settings == null`: 💩 no-op / treat as DEFAULT for host (WebKit requires non-null settings for CUSTOM — we can warn once).

### 5.4 Smoke / demo

**Why:** Acceptance from the bug write-up.

**Add** `examples/browser` or `examples/add-cookie`-style flag, or a small `examples/proxy` / `--smoke-proxy` on an existing demo:

1. Construct `WebView`, call `set_proxy_settings(CUSTOM, new NetworkProxySettings("http://127.0.0.1:<closed-port>", null))` **before** present/attach.
2. `load_uri("https://example.com/")` (or similar).
3. Pass if navigation **fails closed** (no `FINISHED` with real content / load error) within timeout — proves egress used the dead proxy.
4. Optional second path: `DEFAULT` (or no call) loads the same URL and reaches `FINISHED` — proves we did not leave a stale `--proxy-server`.

💩 Full live MITM proxy verification is out of scope unless trivial; fail-closed is enough for CI smoke.

PowerShell expectation (portable demos path as other smokes):

```powershell
& 'C:\msys64\tmp\webview2-gtk\portable-demos\webview2gtk-<demo>.exe' --smoke-proxy
```

Expect `TEST_PASS`.

Also smoke or unit-ish check: after CUSTOM, calling `DEFAULT` before env create results in options **without** `--proxy-server` (can assert via stderr logs if we print the merged args like autoplay does).
