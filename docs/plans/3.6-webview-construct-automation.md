# 3.6 — WebView automation construct properties

**Status:** ✅ complete

ℹ️ Plan emoji: 🔷 user req, 💩 LLM suggestion, ⏳ backlog, 🚫 veto.  
ℹ️ Parent: [3.0-engine-fill-input.md](./3.0-engine-fill-input.md) (3.1 marked construct **✅** early — public API is still a setter).  
ℹ️ WebKitGTK names: `webkitgtk-6.0` `WebView` — `web_context`, `is_controlled_by_automation`, `network_session` are `{ get; construct; }` (web_context is `owned get; construct;`).  
ℹ️ Consumer that hits this: Snappr `src/UI/WebViewAuto.vala` (`#if LINUX` `Object(…)` vs `#if WINDOWS` `set_controlled_by_automation`).

Edits are **Remove** / **Replace with** / **Add**. Proposed Vala matches this tree (tabs, existing docblock style).

---

## Purpose

- 🔷 Make automation-controlled `WebView` construction **the same shape as WebKitGTK**.
- 🔷 Shared app Vala (Snappr `WebViewAuto`) must `Object(web_context: …, is_controlled_by_automation: true, network_session: …)` on Windows with **no** `#if` around those three properties.
- 🔷 Change the three properties to `{ get; construct; }`.
- 🔷 Honor them in GObject construction (`construct` + stop overwriting in `WebView()`).
- 🔷 Drop public `set_controlled_by_automation` (not in webkitgtk-6.0).
- 🔷 Point `examples/automation/` and `docs/automation.md` at subclass `Object(…)` chain-up (`WebViewAuto`, same name as Snappr `src/UI/WebViewAuto.vala`).
- ℹ️ `new WebView() { is_controlled_by_automation = true }` does **not** compile against WebKitGTK (construct-only looks read-only). Compatible consumer is a **subclass** `Object(…)` chain-up, not the brace initializer, not `GLib.Object.new`.

---

## Why this is an upstream API problem

- 🔷 webview2-gtk’s job is to emulate WebKitGTK names so apps `#if WINDOWS` / `using WebView2Gtk` only.
- ℹ️ Today `is_controlled_by_automation` is `{ get; private set; }` plus `set_controlled_by_automation` after `new WebView()`.
- ℹ️ `WebView()` then assigns `web_context` / `network_session` / `is_controlled_by_automation = false` **after** `Object(…)`.
- ℹ️ A subclass that passes construct values in `Object(…)` still gets those three assignments in the parent body, so Windows cannot use the WebKitGTK chain-up.
- 🔷 Fix the library API. Do not keep a Windows-only setter as the documented contract.

## 1. `lib/webview2gtk/webview.vala` — construct properties

**Why:** Match webkitgtk-6.0. Register the controlled view when the construct flag is true.

**Where:** property declarations for `web_context`, `network_session`, `is_controlled_by_automation`; new `construct` block immediately after those three properties.

**Depends on:** none.

### 1a. Property declarations

#### Remove

```vala
	/** WebKitGTK-shaped — context for this view. */
	public WebContext web_context { get; private set; }

	/** WebKitGTK-shaped — network session for this view. */
	public NetworkSession network_session { get; private set; }

	/** WebKitGTK-shaped — this view is owned by an automation session. */
	public bool is_controlled_by_automation { get; private set; }
```

#### Replace with

```vala
	/** WebKitGTK-shaped — context for this view. */
	public WebContext web_context { owned get; construct; }

	/** WebKitGTK-shaped — network session for this view. */
	public NetworkSession network_session { get; construct; }

	/** WebKitGTK-shaped — this view is owned by an automation session. */
	public bool is_controlled_by_automation { get; construct; }
```

### 1b. `construct` defaults + register

#### Add

Place immediately after the `is_controlled_by_automation` property (before `is_loading`). Fill defaults when the caller did not pass construct values. Register when the flag is true.

```vala
	construct {
		if (this.web_context == null) {
			this.web_context = WebContext.get_default();
		}
		if (this.network_session == null) {
			this.network_session = new NetworkSession();
		}
		if (this.is_controlled_by_automation) {
			this.web_context.register_controlled_webview(this);
		}
	}
```

## 3. `lib/webview2gtk/webview.vala` — remove `set_controlled_by_automation`

**Why:** Not a webkitgtk-6.0 method. Registration moves to `construct` (§1b).

**Where:** the method after `WebView()` (docblock + body).

**Depends on:** §1b.

#### Remove

```vala
	/**
	 * Mark this view as automation-controlled(WebKitGTK is-controlled-by-automation).
	 * Call after construct; registers with ''context'' for automation_started.
	 */
	public void set_controlled_by_automation(WebContext context, NetworkSession session) {
		this.web_context = context;
		this.network_session = session;
		this.is_controlled_by_automation = true;
		context.register_controlled_webview(this);
	}
```

## 5. `examples/automation/main.vala` — subclass `Object(…)` chain-up

**Why:** Prove the WebKitGTK consumer shape. Brace initializer `new WebView() { is_controlled_by_automation = true }` is invalid on Linux.

**Where:** `app.activate` view construction (from `get_network_session_for_automation` through `set_vexpand`). New `WebViewAuto` class at end of file (before closing).

**Depends on:** §1–§4.

### 5a. Construction in `activate`

#### Remove

```vala
		var ns = context.get_network_session_for_automation();
		if (ns == null) {
			error("get_network_session_for_automation returned null");
		}

		WebView view = new WebView();
		view.set_controlled_by_automation(context, ns);
		view.set_hexpand(true);
		view.set_vexpand(true);
```

#### Replace with

```vala
		var ns = context.get_network_session_for_automation();
		if (ns == null) {
			error("get_network_session_for_automation returned null");
		}

		WebView view = new WebViewAuto(context, ns);
```

### 5b. `WebViewAuto` at end of file

#### Add

Place after `main()` (end of file). Gtk.Box `orientation` / `spacing` are Windows-widget details for this example only. Shared Snappr Vala does not pass them (WebKit.WebView is not a `Gtk.Box`).

```vala

class WebViewAuto : WebView
{
	public WebViewAuto(WebContext context, NetworkSession session)
	{
		Object(
			orientation: Gtk.Orientation.VERTICAL,
			spacing: 0,
			hexpand: true,
			vexpand: true,
			web_context: context,
			is_controlled_by_automation: true,
			network_session: session
		);
	}
}
```

**Why:** Docs still teach the Windows-only setter and say construct “may land later”.

**Where:** section **Browser setup(shared Vala shape)** (sample + the paragraph under it).

**Depends on:** §1–§5.

## LLM notes

- 🚫 Do not keep `set_controlled_by_automation` as a second public path.
- 🚫 Do not document `GLib.Object.new` or kebab-case `set("is-controlled-by-automation", …)`.
- 🚫 Do not use `new WebView() { is_controlled_by_automation = true }` as the supported form (fails on WebKitGTK construct-only).
- 🚫 Do not change `WebView`’s parent from `Gtk.Box` in this plan (separate emulation gap vs `WebKit.WebView`).
- 💩 If Vala refuses assignment to `{ get; construct; }` inside `construct { }`, pass the three defaults on `WebView()`’s own `Object(…)` instead. Subclass `Object(…)` still overrides.
- ℹ️ `WebContext.register_controlled_webview` stays internal. `construct` calls it when the flag is true.
