# 0.3 — Pacman package signatures on GitHub Releases

**Status:** implemented (needs `WEBVIEW2GTK_GPG_PRIVATE_KEY` secret + next tag release to publish `.sig`)

**Related:** [docs/install.md](../install.md), [`.github/workflows/release.yml`](../../.github/workflows/release.yml)

ℹ️ Plan emoji: 🔷 user req, 💩 LLM suggestion, ⏳ backlog, 🚫 veto.

---

## Problem

`pacman -U https://github.com/.../….pkg.tar.zst` always requests the companion `….pkg.tar.zst.sig` (`RemoteFileSigLevel`). Releases only uploaded the `.pkg.tar.zst` → **404**. That is a release gap, not an install-doc quirk.

Local `pacman -U ./file.pkg.tar.zst` works because MSYS2 `LocalFileSigLevel` allows missing signatures — downloading first is a **workaround**, not the fix.

---

## Fix (release side)

1. 🔷 Sign the pacman package in the Release workflow (`makepkg --sign` / detached `.sig`).
2. 🔷 Publish `mingw-w64-ucrt-x86_64-webview2gtk-*-any.pkg.tar.zst` **and** the matching `.sig` as release assets.
3. 🔷 Ship the packager **public** key in-tree; install docs: one-time `pacman-key --add` + `--lsign-key`, then `pacman -U <release-url>`.
4. 🔷 Private key lives only in GitHub Actions secret `WEBVIEW2GTK_GPG_PRIVATE_KEY` (optional `WEBVIEW2GTK_GPG_PASSPHRASE`).

Also: 🔷 keep `pkgver` in PKGBUILD aligned with the release tag so the asset name matches the tag users expect.

**Maintainer one-time setup:** store the armor private key as repo secret `WEBVIEW2GTK_GPG_PRIVATE_KEY` (optional `WEBVIEW2GTK_GPG_PASSPHRASE`). Public key: [`packaging/msys2/webview2gtk-packager.gpg`](../../packaging/msys2/webview2gtk-packager.gpg), fingerprint in [`webview2gtk-packager.fpr`](../../packaging/msys2/webview2gtk-packager.fpr).

## Out of scope

- Joining official `msys2-keyring` / becoming an MSYS2 packager
- Hosting a full custom pacman repo (`repo-add`) — optional later if we want `pacman -S`
- Backfilling `.sig` onto already-published releases (re-tag / new patch release instead)
