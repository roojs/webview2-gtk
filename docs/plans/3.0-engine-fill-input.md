# 3.0 — Engine click + type (DevTools Input)

**Status:** ⏳ proposed — approve before implement  

**Related:** [1.0-uia-accessibility.md](./1.0-uia-accessibility.md), [docs/a11y.md](../a11y.md)  
**Pattern reference:** `lib/host/win32-ui-webview2-capture.c` (`CallDevToolsProtocolMethod`)

ℹ️ Plan emoji: 🔷 user req, 💩 LLM suggestion, ⏳ backlog, 🚫 veto.

---

## Purpose

- 🔷 Add **engine-level** mouse click and text/key input on the hosted WebView2.
- 🔷 Deliver input through **Chromium DevTools Protocol** (`Input.*`), not OS `SendInput` / UIA keyboard synthesis.
- 🔷 Apps that already locate a control (a11y bounds) can: **click at a point** → **type** (optional trailing Return).
- ℹ️ UIA walk / invoke / `set_value` stay as they are ([1.0](./1.0-uia-accessibility.md)). This plan is **input delivery** only.

---

## Why

- ℹ️ Host already uses DevTools for screenshots (`Page.captureScreenshot` in `win32-ui-webview2-capture.c`).
- ℹ️ Today `vala_webview2_host_a11y_type_text` / `a11y_key_vk` use **SendInput** — OS keyboard synth, same class of problem apps want to leave for fill.
- 🔷 CDP `Input.dispatchMouseEvent` + `Input.insertText` / `Input.dispatchKeyEvent` inject into the page engine while focused.

---

## Proposed API

### Host C (`webview2gtk-host-api.h`)

- 🔷 ⏳ `bool vala_webview2_host_input_click_sync (double x, double y);`
  - Viewport CSS pixels (document viewport of the WebView2 content area).
  - CDP: `Input.dispatchMouseEvent` mousePressed + mouseReleased (`button: "left"`, `clickCount: 1`).
- 🔷 ⏳ `bool vala_webview2_host_input_insert_text_sync (const char *utf8);`
  - CDP: `Input.insertText` with `text`.
- 🔷 ⏳ `bool vala_webview2_host_input_key_sync (const char *key);`
  - For Return / special keys — CDP: `Input.dispatchKeyEvent` keyDown + keyUp (`key` / `code` / `windowsVirtualKeyCode` as needed).
  - 💩 Minimum: support `"Enter"` / `"Return"` for submit-after-type.

### Vala (`WebView2Gtk.WebView` or thin host bindings)

- 🔷 ⏳ Sync wrappers matching other host calls (`capture_screenshot_sync` style).
- 💩 Exact Vala method names at implement — keep next to other host externs.

### Coordinate space

- 🔷 Click `(x, y)` = **CSS viewport** of the WebView2 content (same space CDP Input expects).
- ℹ️ A11y walk nodes today use **screen** pixels (`webview2gtk_a11y_node` comment in the host API).
- 🔷 ⏳ Document how apps map screen (or client) → viewport:
  - WebView HWND / GTK widget origin + DPI scale, or
  - 💩 optional helper `screen_to_viewport` if mapping in every app is error-prone — only add if a demo needs it.

## Implementation steps

### 3.1 Shared DevTools call helper

**Status:** ⏳  

- 🔷 ⏳ Factor or copy the sync `CallDevToolsProtocolMethod` pattern from `win32-ui-webview2-capture.c` into a reusable helper (or a new `win32-ui-webview2-input.c` with the same await style).
- 🔷 ⏳ Method name + JSON params in → success / failure out; return JSON only if needed (click/type usually empty).

**Smoke:** call `Runtime.evaluate` or a no-op Input once from a tiny test path without crashing.

### 3.2 Click

**Status:** ⏳  

- 🔷 ⏳ Implement `vala_webview2_host_input_click_sync`.
- 🔷 ⏳ Declare in `webview2gtk-host-api.h`; wire Vala extern + `WebView` method if that is the public surface.
- 🔷 ⏳ Demo: load a local HTML with a button or input; click known viewport coords; confirm focus/click side effect (e.g. button toggles text).

**Smoke:** click focuses `#q` (or equivalent) in the demo page.

### 3.3 Insert text + Enter

**Status:** ⏳  

- 🔷 ⏳ Implement `vala_webview2_host_input_insert_text_sync`.
- 🔷 ⏳ Implement `vala_webview2_host_input_key_sync` for Enter (at least).
- 🔷 ⏳ Demo: click `#q` → insert `"hello"` → Enter; confirm value / submit handler.

**Smoke:** typed text appears in the field; Enter fires as expected.

### 3.4 Docs

**Status:** ⏳  

- 🔷 ⏳ Update `docs/a11y.md` (or a short `docs/input.md`): CDP input vs `a11y_type_text` SendInput; viewport coords; example sequence click → insert → Enter.
- 🚫 Do not remove SendInput helpers in this plan unless a follow-up says so — keep for AT-SPI string/key compat.

## Out of scope

- 🚫 Changing UIA walk / invoke / `set_value`.
- 🚫 Bundling Selenium / WebDriver servers.
- 🚫 App-specific automation recipes.
- 🚫 Clear-before-type policy (apps decide).
- 🚫 `evaluate_javascript` as the fill path (rejected for this feature — use CDP Input).

## LLM notes

- Mirror screenshot’s sync DevTools await — do not invent a second COM pattern.
- Public API speaks **viewport CSS pixels** for click.
- Prefer `Input.insertText` for printable UTF-8; `dispatchKeyEvent` for Enter.
- Leave `a11y_type_text` / `a11y_key_vk` in place for existing AT-SPI keyboard emulation.
